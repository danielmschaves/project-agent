Pipeline Stages

Six layers · each idempotent · each independently testable

Each stage is a thin function in pipeline/stages.py that calls primitives from the src/project_agent/ package. No stage holds state between calls. Every stage updates the operations log.

1
Ingest — project_agent.ingest.inbox + project_agent.ingest.mcp
File-drop path: scans sources/_inbox/, classifies by extension (.eml → email, .md → doc, .csv/.json → backlog), SHA-256 hashes each file, skips manifest hits, moves new files to typed folders, emits source_ingested events. MCP path (Phase 0.5): fetches from Gmail, Google Drive, and Google Calendar via OAuth2. Both paths write to _inbox/ and let scan_inbox handle dedup and classification. Gated by GOOGLE_TOKEN_PATH.
Shipped · PR #2 + #9
2
Parse — project_agent.llm + project_agent.projects
For each new source: checks the LLM cache (keyed on prompt_version × source_hash). Cache hit → replay byte-identical extraction. Cache miss → call Claude API, cache response. Emits action_added, blocker_added, risk_added, decision_made events. Rewrites project.md.
Shipped · PR #3
3
Warehouse Load — project_agent.warehouse
Reads events.ndjson, loads into DuckDB, materializes views: events (all non-retracted), actions (action_added + action_updated joined), blockers (blocker_added + blocker_updated joined). Excludes retracted and superseded events.
Shipped · PR #4
4
Analyze — project_agent.signals.deterministic
Runs three SQL detectors against the DuckDB views. Each detector returns a list of triggering event_ids, constructs a Signal pydantic model, and appends a signal_detected event with evidence: [event_id, …]. Detectors skip signal_detected events when querying — no circular reasoning.
Shipped · PR #5
5
Render — project_agent.render
Reads project.md, project.notes.md (PM-owned, never written by pipeline), and all signal_detected events. Emits two reports per project: a markdown status report and a full HTML status dashboard using the design system. The HTML includes an editorial header with italic emphasis (coral when signals present, sage when clear), a 5-card fact strip, styled signal cards, action/blocker rows, PM notes section, and a verdict callout. The portfolio pipeline additionally renders a cross-project HTML dashboard with an attention strip (top-3 by composite score), an indicator grid (6 categories × project, colored cells with hover popovers), recent signals panel, silent-project list, and client rollup.
Shipped · PR #6 + #10
6
Commit — project_agent.git
Creates branch auto/<YYYY-MM-DD>, stages all changes to project.md, events.ndjson, reports/, and data/runs/<run_id>.json, commits, and opens a GitHub PR via the gh CLI. The portfolio pipeline (python -m pipeline portfolio) runs stages 1–5 for all projects, renders the portfolio HTML dashboard, then opens a single PR covering all projects with a digest summary. Nothing reaches main without a PM merge.
Shipped · PR #7 + #9

Signal Catalog

Three MVP signals · all deterministic · all fire on the demo corpus

Each signal is a SQL query against the DuckDB warehouse that returns triggering event_ids. Those IDs become the evidence field of a signal_detected event — every signal is traceable back to source documents. No black-box outputs.

SIG-001 · Category: Action
action_aging
High

Detects open actions whose due date has passed without a corresponding action_updated(status=done) event. SQL threshold: >7 days overdue.

Fires on demo corpus because:
Circuit-breaker design doc (BKL-006): due 2026-04-30, completed 2026-05-14 — 14 days late. Evidence chain includes the Apr 28 sync event where it was assigned and the May 14 standup event confirming completion. BAA draft: due 2026-05-02, no completion event — 12+ days overdue as of corpus cutoff.
SIG-002 · Category: Action
action_unowned
High

Detects open action_added events with no owner field and no subsequent action_updated assigning one. SQL: WHERE owner IS NULL AND status != 'done'.

Fires on demo corpus because:
At least 6 unowned actions extracted from the corpus: Partner portal UI (BKL-002), Observability dashboards (BKL-004), HIPAA checklist (BKL-005), JWT key rotation runbook (BKL-009), BAA draft to Partner B (BKL-016), Partner C contact confirmation (BKL-018). Each traced to a source event.
SIG-003 · Category: Blocker
blocker_unowned
Medium

Detects open blocker_added events with no owner. A blocker without a named DRI for resolution has no accountability mechanism and will drift indefinitely.

Fires on demo corpus because:
Partner B unresponsive blocker: extracted from May 12 sync and May 1 follow-up email — no DRI assigned beyond "Alice is watching". JWT runbook blocker from threat model (May 6): no owner field. BAA blocker: similarly unowned. All three appear across multiple source documents.
Anti-circularity invariant
All three detectors query the warehouse with an explicit filter that excludes signal_detected events. SQL signals read only action_added, action_updated, blocker_added, and blocker_updated. This prevents a signal from treating another signal as evidence — a constraint that also applies to the Phase 1 LLM detectors (enforced by prompt instructions).

07/10

Data Contracts

Event schema v0.4 · discriminated unions · append-only NDJSON

Three contracts define everything that persists: the Event (the append-only fact), the Signal (a typed observation with evidence), and the RunLog (per-stage operations audit). All pydantic v2. No dicts, no TypedDicts.

E
Event — append-only fact
The atomic unit of the log. Every action, blocker, risk, decision, and signal is an Event. Written once. Never mutated. Fixed by SHA-256 hash of content. Bad data is corrected via event_retracted.
data/events.ndjson · one JSON object per line
S
Signal — typed observation
Produced by detectors, stored as a signal_detected event payload. Requires non-empty evidence: [event_id, …]. Category, severity, confidence, method, rationale, and recommended_action are all required fields.
Written back to events.ndjson via events.append
R
RunLog — ops audit
Written after every run. Contains per-stage name, status (ok/error/skipped), duration_ms, counts, and optional cost_usd. Total run cost tracked. Committed with each PR so ops history is in git.
data/runs/<run_id>.json · committed every run

    schema_version: int = 1           # bump when shape changes

# Actor — discriminated by actor.kind
Actor = LLMActor | HumanActor | MCPActor | DeterministicActor

class LLMActor(BaseModel):
    kind:   Literal["llm"]
    model:  str                        # e.g. "claude-sonnet-4-6"
    prompt: str                        # e.g. "extract-context.md@1"

class DeterministicActor(BaseModel):
    kind:     Literal["deterministic"]
    detector: str                      # e.g. "action_aging"

# Payload — discriminated by payload.type
Payload = (SourceIngestedPayload | ActionAddedPayload | ActionUpdatedPayload
         | BlockerAddedPayload | BlockerUpdatedPayload | RiskAddedPayload
         | DecisionMadePayload | SignalDetectedPayload | EventRetractedPayload)

class SignalDetectedPayload(BaseModel):
    type:               Literal["signal_detected"]
    signal_id:          str
    signal_type:        str
    category:           str
    severity:           Literal["low", "medium", "high"]
    confidence:         float
    evidence:           list[str]      # non-empty — pydantic enforces min_length=1
    method:             Literal["deterministic", "llm"]
    rationale:          str
    recommended_action: str
Fixing bad data
Never edit events.ndjson directly. The correct mechanism is project_agent.events.append(EventRetractedPayload(retracted_event_id=..., reason=...)). The warehouse load stage excludes retracted events. The original event remains in the log for audit purposes — the retraction event is the correction record.

The three rules that matter most
1. Package Boundary: all state mutation goes through src/project_agent/ APIs. Enforced by tests/test_boundary.py — CI fails if violated.

2. HITL Invariant: the pipeline never commits to main. Always auto/<date> branch + PR. The PM is the only path to main.

3. LLM Cache: every Claude API call routes through project_agent.llm.extract(). Direct anthropic.* calls anywhere outside the package silently break idempotence.
